# Harno scholarships and academic grants

Source `ee-harno` collects factual funding opportunities from the Estonian
Education and Youth Board (Harno). Start at the [international scholarship
entry](https://www.harno.ee/en/scholarships-and-grants/scholarships-studying-and-working-estonia/scholarships-international).
The bounded scope also follows its five adjacent domestic scholarship pages,
Kristjan Jaak and EKKAV, including their directly linked Estonian detail pages.
It does not claim every Harno education project or historical news archive.

## Official access and reuse

Reviewed on 8 October 2026: the entry, eight English hubs and linked Estonian
Kristjan Jaak/EKKAV detail pages returned normal public HTTPS HTML. The official
[robots policy](https://www.harno.ee/robots.txt) permits these routes and excludes
administrative, search and account paths. Normal TLS verification, an identifying
`YouthOpp/1.0 (+https://github.com/YouthOpps/data-pipeline)` User-Agent, origin
robots checks and bounded retries remain enabled. `harno.ee`/`www.harno.ee`
redirects stay inside the verified HTTPS publisher. Requests, redirects,
robots and retries share a process-locked publisher allowance of at least six
seconds between starts and no more than ten starts in any rolling 60 seconds.
Retry-After and stricter robots delays are respected. Separate machines must
not overlap collections for this publisher.

The footer's [personal-data policy](https://www.harno.ee/en/node/145) and
[cookie policy](https://www.harno.ee/node/12) were inspected. They concern
personal information and browser services; no written-permission requirement
for this public factual scholarship collection was found. This is not an open
licence or authorization to reproduce protected text/images wholesale. Output
uses independently written factual summaries, short supporting evidence,
publisher attribution and original links. No recipient data, application
accounts, forms, masked-email endpoints, cookie gates or external providers are
requested. Application systems and linked legal/PDF documents are references,
not collection endpoints.

lists are excluded from fingerprints; actual current funding terms are not.

## Countries, dates and source inconsistencies

The degree/exchange scheme explicitly lists 39 citizenships, normalized as:

`AM AZ BE BR BG CA HR CZ CY EG FI FR GE DE GB GR HU IN ID IL IT KZ LV LT MX MD CN PH PL PT KR SI ES LK TH TN TR UA US`

Aliases: Great Britain → GB, People's Republic of China → CN, Republic of Korea
→ KR, Czech Republic → CZ. This is citizenship eligibility, not destination.
The international programme rejects Russian/Belarusian citizens for 2026/27;
that exclusion does not invent a positive whitelist for summer/research grants
or apply to unrelated Harno programmes. Student nationality is never inferred
from enrollment. The seven Estonia-based awards have explicit host EE.
Foreign mobility/lecture hosts remain unknown: a lecturer or past recipient
country list is not a destination restriction.

Kristjan Jaak degree support requires Estonian citizenship **or** long-term
residence/permanent residence rights, plus Estonian B1. Special-needs support
has citizenship **or** specified residence/study-status alternatives. Individual
EKKAV lecturers may be Estonian citizens **or** qualified foreign nationals
with B1. None becomes an EE-only citizenship whitelist. Research grants require
an overseas academic post; PhD students use the student scheme and postdoctoral
study is excluded. Degree PhD applicants with an Estonian junior-researcher
employment contract are excluded. Full eligibility/funding conditions remain
in the independent summaries and evidence.

Explicit “Estonian time” uses Europe/Tallinn's actual 2026 DST calendar:
1 May 23:59 is `2026-05-01T20:59:00Z`; 31 October 23:59 is
`2026-10-31T21:59:00Z`. Dates without a zone use `YYYY-MM-DD`, preserving
any stated 23:59 clock in prose without inventing an offset. Opening dates
control future-call status; expired calls remain present while published.
Special-needs rolling status is open outside July/August, unknown during that
pause. No page-update, decision, payment or event date becomes a deadline.

Publisher inconsistencies are disclosed rather than silently corrected:
current degree call 2026/27 retains 2025/26 enrollment-document instructions;
summer-school online eligibility refers to 2025 only; Estophilus/EKKAV language
pages retain autumn/open wording despite explicit March 2026 dates. The
explicit dated application window governs expiration, not stale “open” text.

## Run and publication

```sh
python -B adapters/ee-harno/test_adapter.py
python -B adapters/ee-harno/adapter.py
```

The sole live test performs real collection and emits every record as one JSON
document on stdout; diagnostics use stderr. It has no publication token and
writes no output files. Default adapter execution reports non-publishing
metadata. Records use stable source/award/round hashes, source URLs, independent
summaries capped at **600 UTF-16 code units** and supported classification
facts. Metadata provides human-readable publisher attribution. The actual
website `loadData` consumer is part of acceptance verification.

`fetch-ee-harno.yml` runs on main pushes touching only this folder or its own
workflow, manual dispatch and a six-hour schedule (`53 0/6 * * *`). The
repository/main guard, minimum workflow permissions, source-publication App
token restricted to `YouthOpps/data-source` and global publication concurrency
remain enabled. Its only application command is this source's `--publish`.

Publication writes exclusively `datas/ee-harno/{data,metadata}.json` in one
conflict-safe commit. First failure creates no source folder; later failure
preserves last-good data and success timestamp and updates only failure
metadata when safe. Sibling-source changes can rebase; newer own-source data
cannot be overwritten. Only successfully published validated nonempty records
advance durable success. Both fresh and prior Harno records use the strict
600-unit validator; Charles University's source-specific historical-summary
exception is not used here. Live collection/static mocked publication evidence
does not itself claim production execution; maintainers verify after merge.
