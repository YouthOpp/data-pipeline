# Comenius University — FMFI public opportunities

This standalone standard-library adapter covers the Faculty of Mathematics,
Physics and Informatics (FMFI) public current funding, mobility, educational
and job navigation. The assigned source is the [extraordinary scholarship
call](https://zona.fmph.uniba.sk/detail-novinky/back_to_page/fmfi-uk-zona/article/vyzva-na-podavanie-ziadosti-o-jednorazove-mimoriadne-stipendium-call-for-applications-for-ex-9/).
Coverage does not extend to all Comenius faculties, generic news archives or
all historical grants. Source-specific documentation belongs here; the
repository root README is unchanged.

## Public access and factual reuse

All 39 runtime inputs are literal public routes on `zona.fmph.uniba.sk`.
Its [robots file](https://zona.fmph.uniba.sk/robots.txt) contains the unknown
field `~User-agent: *`, with no valid agent groups or disallow rules. Ignoring
that field under the robots standard permits public fetching; it is not an
open-content licence. University copyright and linked privacy notices are
not permission claims. Summaries are brief original factual descriptions,
with attribution, not copied publisher prose, images or applicant documents.

University-root and `fmph.uniba.sk` robots returned HTTP400 during research;
no content on those hosts, alternate host or repaired guessed route was
used. Their unavailable policy/material destinations limit coverage.
The current scholarship PDF is actually linked on the permitted zona host;
its URL was not rewritten from a denied host.

The own FMFI job notice supplies independent factual evidence. The external
[Growni terms](https://growni.sk/vop), section IV, restrict its content to
personal use, so no Growni content or derived-only fields enter collection.
No SAIA, ministry, ticket platform, MSForms, login or applicant-form HTTP is
performed. SAIA remains the named administrator of the NSP notice. Public
application destinations are links only; no contact or submission occurs.

## Durable controls and publication

Controls are deliberately duplicated locally, without cross-adapter imports.
The shared `youthopps-uniba-publisher-v1` budget/collector lock retains all
research/test/production starts, at least six seconds apart and at most ten
in a rolling minute, including robots, redirects and the single HTTP503
retry after thirty seconds. HTTP401/403/429 stop collection; Retry-After
embargo persists, malformed backoff blocks access. Proxy, CA and TLS trust
are inherited. Sanitized diagnostics omit signed URLs, headers and secrets.

Production uses serialized family concurrency and complete actual repository/
main run history, including failed/cancelled attempts. IDs are validated
before filtering; only count drift allows at most three rescans. The newest
completed attempt requires its exact bounded inert `uniba-pacing-state-N`
ZIP/JSON artifact, with schema/repository/source/run/attempt/digest binding.
Restoration merges maximum embargo, blocked OR and last ten unique starts,
plus a sixty-second startup margin. No active family run may overlap.
First-family bootstrap is allowed only after complete history proves no
completed family run; it never repairs missing/expired newest state.
Hard cancellation/runner loss can prevent artifact export; recovery then
requires separate reviewed evidence. Timing state never contains records.

The workflow mints a restricted publication token immediately before the
sole command, with a30-minute workflow limit. A true main-thread POSIX alarm
bounds the process to1290 seconds: operational work ends by1260, reserving
30 for trusted export. Prepublication900/publication180/failure180 phases
are clipped to the original absolute deadline, including blocked reads,
backoff, parsing and output between phases. No alarm renewal/JIT crypto.
CAS may time out before all attempts; failure has its own clipped reserve.
Finally export preserves the original result/error and releases locks.

Only `datas/sk-comenius-university/{data,metadata}.json` is published through
atomic source-scoped Git-tree commits/nonforce CAS. Validate the complete
previous own pair before failure writes. Reconcile uncertain exact-pair
writes before failure metadata; never overwrite newer own data. First
failure creates no folder; subsequent safe failure preserves last-good
data/success stamp. Invalid/foreign prior pairs do not authorize writes.
Collection-end checked timestamps follow all retrieval and validation.
